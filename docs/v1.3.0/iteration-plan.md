# PAE v1.3.0 迭代计划

## 1. 版本定位

PAE v1.3.0 将 v1.2.0 已完成的低代码扩展框架、平台前置分析、人工门禁、知识回流和跨需求复用能力，用于一项真实低代码平台需求，建立从需求输入到开发评审的可追溯设计闭环。

## 2. 核心范围

1. 真实需求材料结构化与来源追踪。
2. 平台与项目边界、需求理解、功能方案、原型和 PRD 五个确认节点。
3. 跨成果物一致性检查与阻断问题分级。
4. 需求变化后的确认失效和影响范围识别。
5. 一项脱敏真实需求的端到端验收；真实公司资料不进入公共仓库。

## 3. 迭代阶段

1. 闭环状态模型与确认门禁。
2. 真实需求输入包与来源索引。
3. 跨成果物一致性和变更影响检查。
4. MasterGo 实际画布、PRD及开发评审验收。
5. 全量回归、发布检查、Tag 和 Release。

## 4. 第一阶段完成标准

- 输出机器可读与 Markdown 闭环状态报告。
- 能识别五个确认节点的 WAITING、READY、CONFIRMED 和 INVALIDATED 状态。
- 需求分析、功能方案或 PRD 变化后，旧确认自动失效。
- 不改变 v1.2.0 已有工作流行为。

## 5. 第二阶段：真实需求输入包

- 使用 `00-sources/source-index.json` 和 `source-index.md` 统一登记需求来源。
- 每项来源记录材料类型、敏感级别、文件大小、SHA-256 和是否纳入分析。
- 文件统一使用安全名称保存，索引不记录本机绝对路径。
- 相同内容禁止重复登记；机密材料可以保存但明确排除在 AI 分析之外。
