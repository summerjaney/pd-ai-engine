# PAE v1.1.0 迭代计划

## 版本主题

产品上下文与增量演进：让 PAE 从单需求正式交付升级为可理解产品历史、分析变更影响并持续维护产品的设计引擎。

## 迭代批次

| 批次 | 范围 | 状态 |
|---|---|---|
| 第一批 | 产品基线 Schema、类型、生成、校验、哈希和覆盖保护 | 已完成 |
| 第二批 | 产品上下文加载、相关内容选择、Prompt 注入和来源追踪 | 已完成 |
| 第三批 | 变更分类、影响分析、产品 Diff 和冲突检测 | 已完成 |
| 第四批 | 产品级成果增量更新、基线接受和历史快照 | 待开始 |
| 第五批 | 连续需求验收、兼容回归和正式发布 | 待开始 |

## 第一批交付边界

- `schemas/v1.1/product-baseline.schema.json` 是产品基线公开契约。
- 首个成功需求自动建立 `product/product-baseline.json`。
- 页面、字段、操作、规则和模块均保留稳定 ID 与来源需求。
- 基线使用 SHA-256 哈希检测损坏和未授权修改。
- 普通需求运行不得覆盖已存在的正式产品基线。
- 后续需求必须在第三、四批通过变更分析和显式接受流程更新基线。

## 第一批验收标准

1. 首次完整工作流成功后生成合法产品基线。
2. 相同输入生成的业务结构和哈希规则确定。
3. 重复运行不覆盖已接受基线。
4. 非法 Schema、重复页面标识、重复路由或哈希不一致被拒绝。
5. v0.3.0—v1.0.0 全量自动化测试无回退。

## 第二批交付边界

- 新需求运行前校验并只读加载当前项目的正式产品基线。
- 依据需求标题和正文选择相关模块、页面、字段、操作及规则，不跨项目加载。
- Prompt 明确区分原始需求、已确认产品事实、前序成果物和知识约束。
- 未匹配的历史事实不会被推断为不存在，也不会把整份基线无差别注入模型。
- `manifest.json.productContext` 记录基线哈希、序号、查询指纹、所选事实及其来源需求。

## 第二批验收标准

1. 无产品基线时保持首次需求行为兼容。
2. 已有产品基线时只选择与新需求相关的历史事实。
3. 不加载其他项目的产品事实。
4. 每个注入项均可追踪到来源需求和修订版本。
5. Prompt 明确保护已确认事实，manifest 可复现本次上下文选择。

## 第三批交付边界

- 基于正式产品基线与本次 Prototype DSL 生成结构化产品 Diff。
- 变更统一分类为新增、修改、删除、迁移、权限调整、流程调整或待确认。
- 影响范围覆盖产品级文档、原型、MasterGo、PRD、手册及验收测试。
- 页面、路由、字段类型、权限和规则冲突分为 `ERROR`、`WARNING`、`CONFIRMATION_REQUIRED`。
- `ERROR` 与待确认项阻止进入基线接受流程；普通运行仍不修改正式基线。

## 第三批验收标准

1. 新增页面、字段、操作和规则被准确识别。
2. 同 ID 字段类型冲突及重复路由被 `ERROR` 阻断。
3. 页面定义、权限、规则覆盖和删除已发布能力必须人工确认。
4. 输出 JSON、Markdown 影响报告及结构化 Product Diff。
5. manifest 可追踪分析所用基线、变更、冲突和受影响成果物。
