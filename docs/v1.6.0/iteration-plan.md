# PAE v1.6.0 迭代计划

## 版本主题

基于平台知识的跨模块复杂需求设计与变更管理。

## 第一批：平台模块图谱

- 建立独立的 `knowledge/platform/modules` 模块目录，不改变 v1.4.0 正式知识实体和晋升契约。
- 描述组织机构、权限、表单、流程和报表五个基础模块。
- 支持 data、permission、configuration、lifecycle、integration 五类依赖。
- 校验重复模块、未知依赖、自依赖、非法依赖类型和目录越界。
- 支持模块查看、列表和 Mermaid 依赖图输出。

## 后续批次

### 第二批：跨模块影响分析（已完成）

- 基于模块名称、职责、核心对象和扩展点识别直接影响模块。
- 根据模块依赖向上展开间接影响，并识别下游回归模块。
- 生成 JSON、Markdown 和 Mermaid 三类分析产物。
- 对平台增强、项目定制、架构评估和证据不足场景提供边界建议。
- 所有边界建议固定为待产品经理确认，不直接替代产品决策。
- 新增脱敏“跨模块数据权限控制”需求样例。

### 后续批次

### 第三批：多方案比较和选择门禁（已完成）

- 根据跨模块影响报告生成现有能力组合、平台增强、产品扩展和项目定制方案。
- 架构高风险需求优先生成架构专项评估方案。
- 从通用性、复用价值、实现成本、影响风险和维护成本五个维度比较。
- 比较报告只能提供建议，默认禁止继续正式设计。
- 产品经理必须明确选择方案并填写实施范围。
- 方案决定绑定需求指纹、影响报告、模块目录版本及完整比较报告；任一内容变化都会使原决定失效。

### 后续批次

### 第四批：复杂需求设计单元和跨成果物追踪（已完成）

- 只有产品经理已选择有效方案后才能生成设计单元。
- 将跨模块影响拆分为能力、数据模型、权限、页面、流程、接口、配置、迁移和回归设计单元。
- 每个设计单元使用稳定 `DU-*` 标识，并绑定需求指纹、影响报告和方案决定。
- 为每类设计单元声明必须覆盖的正式成果物。
- 使用 `[design-unit:<ID>]` 标记追踪需求分析、方案、架构、流程、页面、原型、PRD和评审。
- 成果物缺失或引用缺失时，追踪检查返回 FAIL。

### 后续批次

### 第五批：需求变更和设计单元增量重算（已完成）

- 在方案和设计单元确认后建立显式需求设计快照。
- 比较新旧需求指纹、模块影响级别、依赖类型和判断依据。
- 区分模块新增、修改和移除，并定位受影响设计单元。
- 未受影响设计单元原样保留，变化模块的设计单元重新计算，退出范围的单元明确移除。
- 生成增量设计单元计划，不直接覆盖原正式计划。
- 需求变化后使方案决定、设计单元追踪、功能方案、原型和PRD确认失效。
- 增量计划必须重新完成方案确认后才能升级为正式计划。

### 后续批次

1. 脱敏“跨模块数据权限控制”真实业务验收。

## 发布边界

第一批只建立 v1.6.0 技术基础，不代表版本完成或可以发布。合并、Tag 和 Release 必须在全部批次及保留人工验收边界确认后单独执行。
