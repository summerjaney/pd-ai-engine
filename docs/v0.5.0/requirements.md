# PAE v0.5.0 正式需求说明

## 1. 版本主题

PAE v0.5.0 — Knowledge-driven B2B Design（知识驱动的 B 端产品设计）。

## 2. 版本目标

在 v0.4.0 真实 LLM 全链路基础上，将产品经理的 B 端设计知识从硬编码提示语升级为可维护、可选择、可追踪、可验证的知识资产，并使用真实基础平台需求验证其对成果物质量的提升。

本版本完成后，PAE 不只“调用模型生成”，还应能够说明：本次设计使用了哪些 Pattern、Component 和 Rule，这些知识如何约束原型与 PRD，以及知识是否真正生效。

## 3. 核心价值

- 对产品经理：把隐性的设计经验沉淀为可复用资产，减少重复解释。
- 对生成链路：同类 B 端需求复用一致的页面模式、组件选择和业务规则。
- 对评审验收：成果物中的关键设计决定可回溯到知识条目。
- 对后续扩展：为企业知识库、RAG、插件和多 Agent 提供稳定的知识层契约。

## 4. 功能范围

### 4.1 知识模型

- KNO-001：定义 `Business`、`Pattern`、`Component`、`Rule` 四类知识实体。
- KNO-002：定义实体间的引用关系、适用范围、标签、版本和状态。
- KNO-003：知识条目使用独立数据文件维护，禁止继续仅以 TypeScript 常量硬编码。
- KNO-004：启动时校验重复 ID、无效引用、缺失字段和关系环路。

### 4.2 知识选择与注入

- SEL-001：根据需求内容、业务场景、页面类型和关键词选择知识条目。
- SEL-002：支持显式指定知识条目，并以显式配置覆盖自动选择结果。
- SEL-003：只向当前阶段注入必要知识，避免将完整知识库无差别塞入 Prompt。
- PRM-050-001：Prompt 中区分原始需求、前序成果物、适用知识和输出约束。

### 4.3 知识追踪与验证

- TRC-001：记录每个阶段使用的知识 ID、知识版本和选择原因。
- TRC-002：需求级 `manifest.json` 记录知识库版本与知识使用摘要。
- VAL-050-001：校验原型中的关键页面、字段、操作和规则是否满足适用知识。
- VAL-050-002：评审报告列出已满足、未满足和不适用的知识规则。

### 4.4 真实需求验证

- ACC-050-001：使用基础平台“用户管理”需求完成真实 LLM 全流程。
- ACC-050-002：与 v0.4.0 无知识选择版本进行对照评审。
- ACC-050-003：至少完成第二个不同业务需求的回归，验证知识不是为单一样本定制。

## 5. 首批知识范围

首批只覆盖后台管理类 B 端页面，不追求大而全：

- Business：基础数据管理、流程型业务。
- Pattern：列表页、创建/编辑表单、详情页、状态流转、批量操作。
- Component：筛选区、数据表格、分页器、表单字段、状态标签、确认弹窗、操作栏。
- Rule：必填字段、状态可见、危险操作确认、权限可见性、列表检索、空状态、异常反馈。

## 6. 固定约束

- 项目是长期容器，需求是迭代单元。
- `prototype.json` 继续作为需求级原型单一事实来源。
- Prototype First，PRD 必须由原型及确认结果派生。
- 知识条目必须具备稳定 ID；重命名不得改变 ID。
- 知识选择结果必须可解释、可追踪，不允许只记录一段不可解析的 Prompt 文本。
- Mock 回归不依赖网络或真实密钥。
- API Key 不得进入 Git、日志、manifest、知识文件或成果物。

## 7. 不纳入范围

向量数据库、Embedding 检索、企业私有知识库管理后台、多 Agent、插件市场、多人协作、生产代码生成、自动部署，以及直接写入 MasterGo 画布。

## 8. 发布原则

- 开发期间根 `package.json.version` 保持 `0.4.0`。
- 只有自动化回归、真实 LLM 验收、对照评审和阻断缺陷关闭后，才升级为 `0.5.0`。
- 不得使用 Mock 结果替代真实 LLM 验收结论。
