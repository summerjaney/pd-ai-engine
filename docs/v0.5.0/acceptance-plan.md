# PAE v0.5.0 验收计划

## 1. 验收目标

验证 PAE 能从结构化知识资产中选择与真实需求相关的 B 端设计知识，将其应用到生成链路，并在原型、PRD、Review 和 manifest 中形成可验证、可追踪的闭环。

## 2. 验收层级

- 知识数据验收：Schema、引用关系、版本和状态。
- 自动化回归：Loader、Validator、Selector、Prompt、Trace 和现有 94 项回归。
- 受控生成验收：使用固定模型响应验证知识注入与合规判断。
- 真实 LLM 验收：使用真实 Provider 完成两类 B 端需求。
- 产品人工评审：对照无知识选择与知识驱动两组成果物。

## 3. 发布门槛

- `npm test`、`npm run build`、`npm run check` 全部通过。
- v0.4.0 原有 94 项测试无回归。
- 知识 catalog 无重复 ID、无断裂引用、无非法条目。
- 自动选择结果稳定、可解释，显式选择结果可覆盖自动结果。
- 所有阶段记录知识版本与使用条目，不记录知识全文或密钥。
- 真实 Provider 完成两个需求的全流程。
- 基础平台“用户管理”成果物通过产品经理人工评审。
- 对照评审证明知识驱动版本在完整性、一致性或规则覆盖上有可说明的提升。
- 阻断缺陷全部关闭并具备证据。

## 4. 正式验收需求

### 4.1 主样本

- 项目：`base-platform`（基础平台）。
- 需求：`REQ-050-001-user-management`（用户管理）。
- 覆盖：列表检索、新增、编辑、查看、启停用、批量操作、组织与岗位关联、状态、权限和异常反馈。

### 4.2 回归样本

- 使用与用户管理不同的流程型业务需求。
- 优先复用 `examples/hr-employee-transfer.md`，验证知识选择不会破坏 v0.4.0 已通过的员工调动管理链路。

## 5. 对照评审

同一主样本生成两组成果物：

- A 组：关闭知识自动选择，仅使用 v0.4.0 基础 Prompt。
- B 组：启用 v0.5.0 知识选择、注入和合规校验。

人工评审维度：需求覆盖、页面完整性、组件合理性、业务规则覆盖、跨成果物一致性、可追踪性。评审结论必须包含具体差异，不以主观“更好”替代证据。

## 6. 编号规则

- 测试用例：`TC-050-XXX`。
- 产品缺陷：`PAE-050-XXX`。
- 测试用例与缺陷记录维护双向关联。

## 7. 发布控制

- 完成真实 LLM 验收和对照评审前，版本号保持 `0.4.0`。
- 不得使用 Mock 或受控响应替代真实 LLM 结论。
- 阻断缺陷关闭前，不得创建 `v0.5.0` Tag 或 Release。
