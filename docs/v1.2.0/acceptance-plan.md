# PAE v1.2.0 验收计划

## 1. 验收目标

验证 PAE 能够通过定制化扩展进入低代码基础平台产品设计工作，并在不污染通用内核的前提下完成平台现状分析、人工决策、正式设计、知识回流和跨需求复用。

## 2. 验收范围

- 扩展清单、Schema、发现、校验、依赖与冲突
- 领域扩展、产品扩展和产品工作空间组合
- 扩展上下文的 Prompt 与 manifest 追踪
- 低代码平台前置分析和人工确认门禁
- 平台能力、规则、模式及决策的受控知识回流
- 两项连续低代码平台需求的复用闭环
- v0.3.0—v1.1.0 历史行为兼容

## 3. 真实业务验收场景

1. REQ-201：表单字段联动能力
   - 加载低代码领域与基础平台产品扩展。
   - 首次运行生成前置分析并进入等待确认。
   - 确认为平台能力增强，不调整底层字段模型。
   - 完成需求分析、方案、架构、流程、原型、PRD和评审。
   - 仅接受平台能力和边界决策回流候选。
2. REQ-202：表单字段联动规则复制
   - 重新加载产品工作空间。
   - 前置分析必须命中 REQ-201 回流的“表单字段联动能力”。
   - 来源必须指向已接受产品知识层。
   - 完成人工确认和完整设计工作流。

## 4. 通过标准

- 所有 TC-120 用例通过。
- 全量自动化测试 100% 通过。
- 门禁等待状态、续跑和旧确认失效符合预期。
- 第二需求真实使用第一需求已接受知识。
- 不加载扩展时保持 v1.1.0 通用行为。
- package、lock 和发布目录版本一致。
