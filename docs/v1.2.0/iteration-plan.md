# PAE v1.2.0 迭代计划

## 1. 版本定位

PAE v1.2.0 建设可组合的定制化扩展框架，并以低代码基础平台作为首个正式工作接入场景。主线能力保持领域无关，低代码知识通过领域扩展承载，公司真实资料通过独立产品工作空间承载。

## 2. 交付阶段

1. 扩展协议与兼容基线：清单、Schema、资源类型、来源模型。
2. 扩展加载与组合：发现、校验、依赖、优先级、冲突记录。
3. 工作流接入：将扩展上下文注入需求分析、方案、原型、PRD和评审。
4. 低代码领域扩展：领域对象、规则、模式、术语与迭代工作流。
5. 基础平台私有工作空间：产品档案、模块地图、能力地图和决策记录。
6. 真实需求与复用验收：首个需求交付、知识回流、第二需求复用。

## 3. 当前实现决策

- v1.2.0 第一阶段使用 `extension.json`，与现有 JSON Schema、知识目录和产品基线保持一致，不增加 YAML 运行时依赖。
- 扩展加载顺序由依赖关系决定；领域扩展先于产品扩展。
- 同类型、同 ID 资源允许更具体扩展覆盖，但必须产生冲突记录并保留前后来源。
- 缺失依赖、循环依赖、不安全路径和无效清单直接阻断加载。
- PAE Core 不包含低代码专有判断，领域知识存放在 `domains/lowcode-platform`。

## 4. 第一阶段完成标准

- 扩展清单可通过 Schema 和运行时双重校验。
- 能加载低代码领域扩展并追踪每项资源来源。
- 能按依赖顺序组合领域与产品扩展。
- 同名规则覆盖有明确记录，不能静默发生。
- 不加载扩展时，v1.1.0 全量测试保持通过。
