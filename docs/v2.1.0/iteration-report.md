# PAE v2.1.0 迭代总结

## 版本主题

使用 PAE 完成低代码平台 AI 能力规划与产品设计。

## 完成结果

v2.1.0 使用低代码基础平台作为真实业务方向，以“AI 应用搭建助手”为首期 MVP，以采购审批应用作为端到端验证案例，完成从产品规划到评审交付的五轮迭代。

| 轮次 | 能力 | 主要结果 |
|---|---|---|
| 第一轮 | AI 产品规划 | 产品基线、AI 能力蓝图、场景优先级、MVP 草案及产品经理确认门禁 |
| 第二轮 | 需求建模 | 6 类业务对象、7 步主流程、10 类状态、6 类异常及 8 条验收标准 |
| 第三轮 | 配置契约 | 应用、实体、表单、流程、权限五类 DSL，分模块校验与局部重新生成 |
| 第四轮 | 产品原型 | 5 个信息架构区域、14 个页面、28 条交互及 106 个 MasterGo 节点 |
| 第五轮 | 正式交付 | PRD、8/8 追踪矩阵、设计评审包及真实项目验证报告 |

## 新增 CLI

```text
pae ai plan

pae ai finalize
```

## 核心产品原则

- AI 负责理解和生成，低代码引擎负责校验和执行，用户负责最终确认。
- 整包生成、分模块校验、局部修复、整体发布。
- 未经需求确认、方案确认和发布确认，不得生成或写入正式配置。
- 发布前必须展示差异、建立快照；失败即停止并整体回滚。
- 产品规划建议、真实画布、模型质量和业务评审不能由自动化结果替代。
